# Terminal v3 · 行为、迁移与验收

2026-10-13。基于本地 `3844fe8` 的可靠研究 v2 继续迭代；保留既有策略标识、行情库、历史任务和原模拟账户数据库。当前引擎标识为 `daily-v3`，模型评估仍遵循 `causal-wf-v2`，新增产物标明 `research_revision=terminal-v3`。

## 环境与结构

Python 3.12.13 独立 `.venv`，由 `pyproject.toml` / `uv.lock` 管理并导出兼容 requirements。验证环境主要版本：FastAPI 0.143.0、Starlette 1.7.0、PyArrow 23.0.1、NumPy 2.2.6、Pandas 2.3.3、SciPy 1.15.3、scikit-learn 1.6.1。升级修复了审计发现的旧 Starlette / PyArrow 漏洞，也消除了旧 Python 的 LibreSSL 警告。

应用初始化、公开模型、只读路由、回测计算、数据提供方、参数实验与结果分析已分模块。保留 `main` 的兼容业务入口，现有调用和测试可继续使用。因子页面拆出配置、任务状态、结论和图表模块，终端使用六个主要入口与独立的历史结果比较组件。

队列仍为两个子进程槽、20个等待/运行任务。数据库文件锁阻止重复协调器；进程启动和调度异常不使线程退出；取消/中断终态不允许迟到成功覆盖；关闭时终止计算进程组并保留未完成任务状态。

## 研究契约与接口

新增接口：

| 路径 | 用途 |
|---|---|
| `GET /api/terminal/status` | 不主动抓行情的缓存概览、默认日期、计算槽状态 |
| `POST /api/experiments/jobs` | `base: BacktestRequest` 与1至12个参数候选 |
| `POST /api/research/jobs/{id}/replay` | 完成的回测或参数实验使用原快照重放 |
| `GET /api/research/assistant/status` | 是否配置模型；默认关闭 |
| `POST /api/research/analysis` | 分析用户选择的1至4个完成任务，`use_external` 默认 false |

实验候选只改变持仓上限、止损、止盈、持有天数和权重方式。前60%日期用于历史准备，随后20%选择参数，最后20%仅评估胜出配置；排名指标为验证期扣成本净收益，平手按候选顺序。测试账户重新从相同初始现金开始，不延续验证账户持仓。实验不是以机器学习训练替代策略回测；数据、策略、成本和区间均保存。

逐窗口因子研究使用120训练／40验证／20预测交易日，训练和验证边界清除跨界标签。特征选择、裁剪和模型混合只使用历史窗口；无有效样本外窗口时拒绝将普通模型评分伪装成样本外结果。HGB 仅在用户开启后加入候选，关闭随机早停，混合权重仍只在历史验证窗口选择。

重放验证行情、基准内容哈希、代码与依赖锁、计算环境版本、当前策略版本和模型产物指纹。发生变化时返回可解释错误，需使用原环境，或新建实验比较差异。只有普通回测与参数实验提供该精确重放接口；因子报告保留原有不可变归档和版本流程。

分析助手只发送选择结果的参数、指标和诊断，不发送全库、账户持仓或凭证。返回结构经校验；外部调用失败、无配置或非法动作响应退回本地报告。建议不会自动执行。外部模型真实供应商调用未配置，本轮验证使用传输替身覆盖响应和失败行为。

真实 A 股验收发现旧缓存混入不同复权口径。完成公司行动验证后，严格指标完全从未复权价格重建，旧复权价异常不参与指标；未复权除权参考价发生无法解释的变化仍拒绝执行。已验证的现金分红、送转使用声明事件计算参考价，并按支付日、股份可用日计入账本。配股及其他未支持事件不推测执行。

证券印花税日期分段依据 [税务总局公告](https://liaoning.chinatax.gov.cn/art/2023/8/27/art_5869_7442.html)；除权参考价公式依据 [深交所说明](https://investor.szse.cn/institute/video/classroom/operation/t20190131_564542.html)；ETF 回转规则参考 [上交所说明](https://www.sse.com.cn/assortment/fund/etf/question/c/c_20240118_5734755.shtml)。每个品种的实际规则仍可通过 instrument 配置指定。

日线触价、触板拒单和成交量容量是明确的近似；不能还原订单簿。现金分红按声明金额计提，未建模差别化股息税。固定股票样本不声称已经消除幸存者偏差。基准缺失显示未提供，不解释为零收益。

## 迁移与回滚

- 原 `backend/virtual_trading.db` 已使用 SQLite backup 备份；逐表内容比较一致。测试、预览、验收均使用隔离数据库，不改正在运行的服务。
- 旧 Python 3.9 环境保留。新启动脚本选择 `.venv`；旧环境不能运行 v3，`main` 提供明确迁移提示。部署前停止原服务并使用新启动入口；本轮不替换现有运行服务。
- 普通策略计算保留，新引擎行为通过 `daily-v3` 标识。已有旧版本共享账本只读保留、停止推进，不偷偷以新规则接续。
- 如已有 v2 共享账户，先停止服务，在 backend 执行 `uv run scripts/migrate_account_engine.py` 预览；明确迁移时执行同命令加 `--apply`。工具先备份，再原样归档旧账户。下一次明确执行日线模拟时创建新的100万元基准账户，不重算旧持仓。
- 原策略激活状态不变，新模型作为研究候选，仍需既有影子观察／批准／激活流程。旧未版本化 ML 配置可能需要重新体检生成完整配置指纹。
- 回滚到旧代码时使用原 Python 环境和部署前备份；新状态目录保留，不把新账本混进旧数据库。
